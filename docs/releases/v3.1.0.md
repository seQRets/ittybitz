# v3.1.0 🦕 Stegosaurus — Argon2id key derivation

The first change to how IttyBitz turns a password into a key since v1.0.
Follows [v3.0.17](v3.0.17.md). Anything encrypted with any earlier version
still decrypts exactly as before.

## What changed

- **New files use Argon2id.** IttyBitz now derives the encryption key with
  Argon2id (RFC 9106), a memory-hard function, at 64 MiB of memory and 3
  passes. Every guess an attacker makes now costs 64 MiB of memory as well
  as time, which blunts the GPU and custom-hardware attacks that make
  PBKDF2 cheap to run at scale. This closes the one open item in the
  project's security audit. The cipher is unchanged: AES-256-GCM.
- **A new container format, v2.** New files begin with `IBTZ` and version
  byte 2, followed by the Argon2id settings, so a later release can raise
  them without another format change. The whole header is authenticated
  along with the encrypted data. A key file now enters the derivation as
  Argon2's secret input (its SHA-256) instead of being appended to the
  password.
- **Older files keep opening.** Files and text from every earlier release,
  v1.0 onward, still decrypt through the original PBKDF2 path, and the test
  suite replays real ciphertexts from every release on every change.
- **The Recovery tool reads v2 too,** and its own source now describes all
  three formats in plain words, so the data stays recoverable with any
  standard Argon2id and AES-256-GCM tool even if the page itself never runs.
  It grows from 30 KB to 43 KB.
- **Plainer progress messages, and a spinner in the Recovery tool.** While
  a key is being derived, the app now says "Securing your secret…" or
  "Unlocking your secret…" (or "file", or "files"), instead of a technical
  note about key derivation. The Recovery tool's Decrypt button now turns
  into a spinner while it works, as the app's button already did. The
  spinner keeps turning even while the key derivation keeps the page busy,
  and stays still for anyone who has asked their system to reduce motion.

## How Argon2id is built

Web Crypto has no Argon2id, so IttyBitz carries its own. The heavy part is a
1.4 KB WebAssembly module, hand-written in readable text format
(`scripts/build/argon2.wat`) and assembled by a small, dependency-free script
(`scripts/wat.mjs`); there is no compiler toolchain to trust. The build
writes the identical block into both files, and CI rebuilds it from source
on every change and fails if the published bytes differ. The test suite
checks the result against the official RFC 9106 test vector and against
Node's own Argon2id across many parameter sets, and swaps whole v2 files in
both directions between the app, the Recovery tool, and an independent
implementation built only from Node's Argon2id and Web Crypto.

To compile that module, the page's security policy now includes
`'wasm-unsafe-eval'`. It allows the page to compile its own embedded
WebAssembly and nothing else: `eval()` and injected scripts stay blocked,
and every script block is still pinned by its hash.

Deriving a key takes about a tenth of a second on a recent laptop, and
somewhat longer on a phone.

## For users

- **Save the new Recovery tool.** Copies of the Recovery tool or the app
  from v3.0.17 or earlier cannot open files made with this release; they say
  the file needs a newer version of IttyBitz. Download this release's
  Recovery tool and keep it next to your encrypted files, replacing any older
  copy.
- **Existing files are not changed.** They keep their PBKDF2 protection
  until you decrypt them and encrypt them again with this version.
- **Browser support.** Argon2id needs a browser from 2022 or later (Chrome
  97, Firefox 102, Safari 16). Older files still open in older browsers.
