# v3.0.5 🦕 Iguanodon — UTF-8 QR codes, save-your-password notice, new layout

A bug-fix and layout release from a code review of both the main app and the
recovery tool, building on [v3.0.4](v3.0.4.md). The cryptography, container
format, wordlist, and self-tests are untouched; `npm run test:crypto` still
passes every historical fixture in both directions.

## Layout

- **The app name is the headline.** The sticky header bar is gone. The logo
  now sits centred at the top, larger, with **IttyBitz** as the page title and
  "Encrypt everything. Trust nothing." as the tagline beneath it — the same
  shape as the recovery page.
- **Encrypt / Decrypt is the first control in the card**, as a full-width
  switch with lock and unlock icons, directly above the File / Text choice.
  It was previously a small toggle in the top-right corner of the header.
- The GitHub footer link now matches the colour of the other footer links.

## Fixes

- **QR codes of decrypted text now encode UTF-8.** The vendored QR library
  defaulted to an encoder that keeps only the low byte of each UTF-16 code
  unit, so a plain QR of decrypted text containing anything outside Latin-1
  (emoji, Cyrillic, CJK, and accented characters on many scanners) scanned to
  garbage. The app now selects the library's UTF-8 encoder before drawing, the
  "fits in a QR" check measures UTF-8 bytes rather than string length, and a
  text that exceeds QR capacity now reports "too long to fit in a QR code"
  instead of failing silently. Base64 output and SeedQR were never affected
  (both are ASCII).
- **Save-your-password notice, before it is too late.** After a successful
  encrypt the password field is cleared for safety, which meant a generated
  password that had not been copied was gone with no warning. The app now
  says so the moment a password is accepted — when the border turns green as
  you type, or when you click Generate — while the password is still on
  screen to save. The post-encrypt message is a reminder to store the saved
  password securely.
- **Downloads no longer revoke their blob URL synchronously.** Both the main
  app and the recovery tool revoked the object URL immediately after the
  download click, which Safari can treat as cancelling the download. The
  revoke is now deferred.

## Tooling

- **`update-csp-hashes.mjs` walks the markup like the HTML parser.** The
  previous regex would treat a literal `<script>` inside an HTML comment as a
  real block and hash the wrong bytes, pinning a hash the browser never
  matches and silently killing the page. Found while updating comments; the
  scanner now skips comments and reads each script body to its real close.
- **Stale comments removed** from the shipped files: the CSP comment now
  describes the hash-pinned `script-src` rather than `'unsafe-inline'`, and
  the app header no longer refers to the removed React component.

## For users

Nothing to do. Existing `.ibitz` files and encrypted text decrypt exactly as
before. If you have shown a plain QR of decrypted non-English text from an
earlier version, re-generate it with this release.
