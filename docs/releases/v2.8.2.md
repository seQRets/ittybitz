## v2.8.2 🦕 Triceratops — Next.js security release

A dependency patch that lands upstream fixes for two **Critical** Next.js advisories. **Cryptography is unchanged** — `src/lib/crypto.ts` was not touched, and all 62 regression checks pass against real ciphertexts from every release back to v1.0.

### 🔒 Next.js 16.3.1 → 16.3.3

Next 16.3.3 patches two Critical advisories:

- [GHSA-p293-qw3h-jr36](https://github.com/vercel/next.js/security/advisories/GHSA-p293-qw3h-jr36) — unauthenticated remote code execution on Windows-hosted servers
- [GHSA-2xp9-vwfh-vxw4](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4) — unauthenticated remote code execution in the Image Optimization API when AVIF files are optimized (affects `next < 16.3.3`)

**Neither advisory is reachable in IttyBitz**, for three independent reasons:

- The app is a static export (`output: 'export'`). There is no Next.js server anywhere — GitHub Pages serves pre-rendered files, and the build output contains no `_next/image` route.
- `next/image` is never imported. The Image Optimization API — the vulnerable code path — is not present in the build.
- No AVIF assets exist in source, config, or `public/`, which is the trigger condition for that advisory.

The Windows RCE likewise requires a running Next server on Windows; CI runs Ubuntu and production runs no server at all.

The upgrade is shipped anyway. Staying current on a Critical RCE in the framework is worth doing on principle, and here it costs nothing.

**Worth recording:** `npm audit` reported **0 vulnerabilities** against the vulnerable `next@16.3.1`, because the npm advisory database had not yet mirrored these GitHub advisories. A clean `npm audit` is evidence of no *known, mirrored* vulnerabilities — not evidence of no vulnerabilities.
