## v2.9.3 🦕 Archaeopteryx — offline PWA hardening

A service-worker robustness fix for installed PWAs that launch offline. **Cryptography is unchanged** — `src/lib/crypto.ts` untouched, Recovery decrypt core byte-identical, 70/70 regression.

### 📴 Never a blank screen offline again

If you install the PWA and later open it with no internet, and the app shell was not fully cached on that device yet (for example the app was installed on an *older* service worker that predated the offline fix), the launch showed nothing but the manifest's blank background colour — an orange screen with no explanation.

Two things changed in the service worker:

- **The offline navigation can no longer resolve to nothing.** It tries the network, then the cached app shell, then a small built-in page that says plainly: *"This device has not finished caching the app for offline use. Connect to the internet once and reopen IttyBitz to complete setup."* An honest, actionable message instead of a silent blank.
- **This release re-triggers a full precache on every device.** A service worker only re-runs its install step — the atomic, all-or-nothing precache of the entire app — when `sw.js` changes. Bumping the cache version here forces exactly that on each device's next online open, so a PWA stuck on an older worker repairs itself.

**If your installed PWA is currently failing offline:** open it (or ittybitz.app) once while online and give it a few seconds, then fully quit and relaunch. It will have re-cached and will work offline. If it somehow still fails, uninstall and reinstall the PWA for a guaranteed clean install.

- Fresh install, server stopped: full app renders offline (23 entries cached).
- Empty cache + offline: the built-in setup message renders — no blank screen.
- Recovery path: one online open repopulates the cache and offline rendering returns.
- Typecheck, production build with CSP hashes and zero residual `unsafe-inline`, `npm audit` clean, crypto regression 70/70.
