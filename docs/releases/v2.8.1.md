## v2.8.1 🦕 Triceratops — generator bug fix, BIP-39 test coverage, build hardening

A patch release built almost entirely from outside contributions. **Cryptography is unchanged** — `src/lib/crypto.ts` was not touched, and the regression suite passes against real ciphertexts from every release back to v1.0.

### 🐛 The Generate button could produce a password the app then rejected

Clicking **Generate** produced a 32-character draw from a 91-character charset. That draw missed the digit class about **2.4% of the time** — `(81/91)^32` — and `processData`'s strength gate would then reject a password the app had just created. From the user's side: click Generate, click Encrypt, get *"Weak Password"* back, roughly **1 press in 41**.

The comment above `isPasswordStrong` claimed a generated password "can never be rejected by this check." That reasoning was wrong: sharing a charset guarantees no *invalid characters*, but says nothing about whether a random draw covers every required class. Both the code and the comment are fixed.

`generatePassword` now resamples the whole password until it satisfies the gate. Resampling entirely — rather than splicing a digit into a fixed position — keeps the distribution uniform over the set of strong passwords. Measured over 200,000 draws: **0 rejections** (previously 4,833), averaging 1.025 resamples with a maximum of 4. Verified again in the production build: 200 consecutive Generate clicks, zero failures.

Thanks to [@slimbotdiplo-wiz](https://github.com/slimbotdiplo-wiz) for finding this ([#37](https://github.com/seQRets/ittybitz/pull/37)).

### 🔒 BIP-39 and SeedQR are now gated in CI

`src/lib/crypto.ts` has had 45 checks behind it since v2.7.3, but `src/lib/bip39.ts` had none — despite feeding hardware-wallet imports directly, where a wrong word index yields a QR that scans cleanly into the **wrong wallet**: silent and unrecoverable.

A fifth section in the existing suite now pins it — no new file, no framework, no dependency:

- 12/18/24-word canonical mnemonics validate, report correct entropy width, and encode to the expected Standard SeedQR digit string (SeedSigner spec, each index zero-padded to 4 digits)
- case and whitespace normalization
- every failure reason reachable and correctly labelled, including the `seedShaped` flag behind the red-border warning
- `toStandardSeedQR` refuses a non-wordlist word rather than emitting a short payload

The implementation was already correct; this pins it so a future refactor can't quietly change SeedQR output. **The suite is now 62 checks.** ([#38](https://github.com/seQRets/ittybitz/pull/38))

### 🛡️ `npm ci --ignore-scripts` in the build job

`deploy.yml` already scoped the build job's permissions on the grounds that `npm ci` runs untrusted transitive install scripts. No package in the lockfile actually declares one — **0 of 173** — so disabling them costs nothing today and removes the execution path entirely if a dependency adds one later. This also brings `deploy.yml` in line with the crypto-regression workflow, which already avoids `npm ci`. ([#39](https://github.com/seQRets/ittybitz/pull/39))
