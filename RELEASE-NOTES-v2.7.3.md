## v2.7.3 🦖 Velociraptor — a permanent crypto gate, plus two clean major bumps

Maintenance with one genuinely new safeguard. **No user-facing changes, and cryptography is unchanged** — `src/lib/crypto.ts` was not touched, and this release adds the machinery to keep proving that automatically, forever.

### 🔐 Crypto regression suite, now part of the repo

`src/lib/crypto.ts` is frozen because people hold long-horizon (25-year) secrets encrypted with it — but until now the only thing verifying that was an ad-hoc script re-created by hand each time. It is now a permanent, versioned gate:

```bash
npm run test:crypto
```

It also runs in CI on every push and pull request.

The core of it is **two checked-in fixtures**: a real v1 `IBTZ` ciphertext produced by the v2.7.0 build, and a legacy **v0 headerless** ciphertext constructed from raw Web Crypto primitives rather than through `crypto.ts`. Because these are external artifacts rather than values regenerated by the code under test, they catch the one failure mode a round-trip test cannot — encryption and decryption changing *together* in a way that remains self-consistent but can no longer read files that already shipped. New fixtures get appended over time; old ones must keep passing forever.

Eleven checks in total: 2 fixtures, 2 round-trips (text, and binary with a key file), 3 container-format assertions (`IBTZ` magic, version byte, header + salt(16) + IV(12) layout), and 4 rejection cases — wrong password, wrong key file, **tampered ciphertext** (proving AES-GCM authentication actually rejects modified data), and truncated input.

Two deliberate design choices: the suite adds **no new dependencies** (it runs TypeScript directly via Node's native type stripping, avoiding a transpiler), and the CI job deliberately skips `npm ci` — `crypto.ts` has zero imports, so nothing needs installing and no untrusted dependency install scripts execute in the job that guards the cryptography.

### 📦 Two major dependency upgrades, individually verified

**`qrcode.react` 3.1 → 4.2.** This is the library that renders your SeedQR, so it got the most scrutiny. v4 deprecates `includeMargin` in favour of `marginSize`; both call sites were migrated (`false` → `0`, `true` → `4`), and the 1024×1024 export now carries a comment recording that the 4-module quiet zone is QR-spec required and must not be reduced — that PNG gets printed as a seed backup, and scanners need the full margin to acquire the code. (v4's one hard breaking change, removal of the deprecated default export, does not apply here — the app uses the named `QRCodeCanvas` import.)

Rather than assume the output was unchanged, a v3 baseline of the same SeedQR was captured *before* upgrading and re-measured after:

| | v3 | v4 |
|---|---|---|
| Module fingerprint | `1201774550` | `1201774550` |
| Dark-module ratio | 0.49365234 | 0.49365234 |
| 256px preview quiet zone | 0px | 0px |
| 1024px export quiet zone | 124px (4 modules) | 124px (4 modules) |
| 256px PNG hash | `844706547` | `844706547` |
| 1024px PNG hash | `621268233` | `621268233` |

Identical PNG hashes mean the exported image is **byte-identical**: a SeedQR printed before this release and one printed after are the same artifact.

**`lucide-react` 0.420 → 1.27.** v1 removed all brand icons; none of the 17 icons used here are brand icons, and typecheck passed unmodified — confirming no renames affected us, including `Loader2` (a legacy alias for `LoaderCircle`, and the one real risk). v1 also drops the UMD build (unused here) and now defaults `aria-hidden` to true, which is correct since every icon in this app is decorative alongside a text label.

**Evaluated and deliberately deferred:** Tailwind CSS v4 and React 19. Tailwind v4 would require rewriting the config and CSS while raising the browser floor to Safari 16.4+ / Chrome 111+ / Firefox 128+ — a poor trade for an app meant to run on old, air-gapped machines. React 19 is not required by Next 16 (which accepts React 18 or 19) and can wait for a deliberate pass.
